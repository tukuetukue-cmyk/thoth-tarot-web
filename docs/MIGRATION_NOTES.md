# MIGRATION_NOTES.md

## 現在のフロントエンド プロジェクトの状態
- **リポジトリ**: `thoth-tarot-web` (Webフロントエンド専用リポジトリ)
- **主要コンポーネント**
  - 静的 HTML/CSS/JavaScript で構成されており、ビルドツール（Webpack, Vite 等）は使用していません。
  - `public/` フォルダ内のファイル群がそのまま公開アセットとなります。
- **デプロイ環境**
  - **Firebase Hosting**: `cinnamonclove-7be76` プロジェクトに対してデプロイされます。リポジトリ内に `firebase.json` および `.firebaserc` が実在します。
- **バックエンド API (`thoth-tarot-api`)**
  - 別リポジトリで管理されており、本番用の API URL は `https://thoth-tarot-api.onrender.com` です。

## 開発・運用上の注意点
- **1日3回制限の仕様**: ユーザーアカウントベースではなく、ブラウザの `localStorage` を利用したクライアント側の制限です。`localhost` 環境で実行した場合は、この回数制限の判定のみが無効化（バイパス）されます。
- **APIエンドポイントの向き先**: 
  - `localhost` での実行時も、基本のリーディングやチャット機能は **本番の API (`thoth-tarot-api.onrender.com`)** に接続します。
  - 霊的カルテの機能のみ、`localhost` 時はローカルの API (`http://localhost:8000`) に接続する挙動になっています。
- **3枚引き機能**: コード上には3枚引きのロジックが残っていますが、通常の画面上では非表示扱いです。
- **デバッグパラメータ**: URL に `?force_card=xx` を付与して特定のカード結果を強制表示する仕組みは、本番環境でも稼働する既知の仕様です。
- **Firebase 機能の休眠**: Firebase Authentication、Firestore、Premium（有料版）関連の機能はソースコード内に残存していますが、完成しておらず休眠状態です。設定の `apiKey` はプレースホルダーであり、参照先DOMや変数に不整合があることが分かっています。

## 既知の不整合と要確認事項
Codex が今後開発を進めるにあたり、以下の不整合については推測で修正せず、エクツ（オーナー）の判断を仰いでください。
- **絵文字ルール**: ドキュメント上の絵文字禁止令と、実際のコード内にある可視絵文字の混在。
- **商用リンク方針**: Ko-fi等リンクの「永久削除」と「一時非表示」の記述の衝突。
- **多言語対応の不完全さ**: 言語切り替え時に、動的生成されたテキストや一部画面への即時反映が行われない問題。

## セキュリティ上の既知の課題 (要対応)
現行実装には以下の課題がありますが、今回修正は行っていません。
1. `innerHTML` にユーザー入力やAIレスポンスを挿入している事による DOM XSS リスク。
2. 鑑定回数制限がクライアント側の `localStorage` に依存している点。
3. バックエンド API 呼び出し時の認証の不在。
4. CSP / SRI 等のセキュリティヘッダーが設定されていない点。
5. `localStorage` に個人情報（名前、生年月日、相談内容、AI結果）が保存されている点。
6. リクエストの timeout、`AbortController`、および多重送信対策がない点。

## 今後 Codex が変更する際に注意すべき箇所
- WebとAPIの責務分担を明確に意識してください。フロントエンドは UI 描画とクライアント状態管理に特化し、生成ロジックは API 側に委ねられています。
- 将来的に Firebase 認証や Firestore を有効化する際は、中途半端な既存コードとプレースホルダー設定の整理が必要です。
- 各種 API リクエスト先の環境ごとの自動切り替え（ローカル環境と本番環境のスマートなルーティング）は、今後の課題として整理が必要です。
