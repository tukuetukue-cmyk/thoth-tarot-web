# MIGRATION_NOTES.md

## 現在のフロントエンド プロジェクトの状態
- **リポジトリ**: `thoth-tarot-web` (Webフロントエンド専用)
- **バックエンド API (`thoth-tarot-api`)**: 別リポジトリ。本番用 API URL は `https://thoth-tarot-api.onrender.com`。
- **カードデータの責任所在**: Web側 (`public/src/js/cards.js`) と API側 (`tarot_data.json`) の双方にデータが存在し、どちらが正本かは未確定です。

## 開発・運用上の注意点
- **1日3回制限の仕様**: ユーザーアカウントベースではなく、ブラウザの `localStorage` を利用した制限です。`localhost` 実行時はこの回数制限のみが無効化されます。
- **APIエンドポイントの向き先**: `localhost` でも基本機能（リーディング/チャット等）は本番 API に接続し、霊的カルテのみローカル API に接続します。
- **3枚引き機能とディグニティ**: 3枚引きの処理はコード上残っていますが、UIでは休眠状態（非表示）です。ディグニティ計算はAPI側に存在しますが、現在の通常UIは1枚引きのみ公開されているため、ディグニティ機能がUIで利用されているとは断定できません。
- **霊的カルテのUI**: 文章スクロールと生命の樹SVGハイライトの連動が中心機能です。（象徴モーダルはメイン画面、象徴辞書は生命の樹画面の機能です）

## Codex の変更ルール (行動規範)
Codex が今後開発を進めるにあたり、以下のルールを厳守してください。
1. 変更前に必ず実装計画を提示すること。
2. ユーザーの合意後に実装すること。
3. 依頼外の変更は絶対にしないこと。
4. エラーを発見しても、勝手に修正せず報告すること。ただしユーザーが明示的に「自律的に修正してよい」と指示した作業範囲内では、自律修正してよい。

## 既知の不整合とセキュリティ上の課題
- **不整合**: 絵文字ルール、商用リンク方針、多言語対応の不完全さについては推測で修正せず確認すること。
- **セキュリティ (要対応)**: `innerHTML` の DOM XSS リスク、クライアント依存の回数制限、API認証不在、CSP等未整備、`localStorage` への機密情報保存、多重送信対策の欠如。
