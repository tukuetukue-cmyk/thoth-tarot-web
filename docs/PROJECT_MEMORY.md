# PROJECT_MEMORY.md

## プロジェクトの永続的記憶 (フロントエンド)

このファイルは **Codex** へ引き継ぐ際に、Webリポジトリ全体の重要情報・前提条件・設定値を一元管理するためのメモリです。

### 1. クライアント側の仕様と制限
- **1日3回の制限**: 判定はサーバーサイドではなく、ブラウザの `localStorage` 単位で管理されています。
- **localhost でのバイパス**: 実行環境が `localhost` の場合、**この回数制限のみが無効化** されます。
- **デバッグ仕様**: クエリーパラメーター `force_card` を使用した強制カード表示は、本番環境でも利用可能な既知の仕様です。
- **3枚引き**: 3枚引きのロジックはコード上に残っていますが、通常のUI上では休眠状態です。
- **ディグニティ**: ディグニティ計算はAPI側に存在しますが、現在のWeb通常UIは1枚引きのみ公開されているため、UI上で利用されているとは断定できません。

### 2. カードデータの責任所在 (未確定事項)
- Web側には `public/src/js/cards.js` として78枚のカードデータが存在し、カード抽選・名称・キーワード・象徴・画像対応に利用されています。
- 一方、API側にも `tarot_data.json` が存在しており、**どちらが正本かは現在未確定**として記録されています。

### 3. デザイン・仕様における既知の不整合 (要エクツ確認)
- **商用リンク**: Ko-fiなどの商用リンクについて、「永久に削除する」方針と、「一時的にコメントアウトで非表示にする」記述が衝突しています。
- **絵文字の扱い**: サイト全体の絵文字使用禁止というルールと、実装内にある可視絵文字の混在。
- **多言語対応**: 日本語/英語の切り替えは完全ではなく、動的な結果や一部の画面では即時反映されません。

### 4. セキュリティ上の要対応事項 (コード修正は行わず文書化のみ)
- **DOM XSS リスク**: `innerHTML` にユーザー入力やAI出力を入れている箇所。
- **クライアント依存の制限**: 鑑定回数の制限が `localStorage` に依存している点。
- **API認証の不在**: API 呼び出し時に認証がない点。
- **ヘッダー未整備**: CSP / SRI、セキュリティヘッダーが未整備。
- **機密情報の保存**: `localStorage` に個人情報（名前、生年月日、相談内容、AI結果）が保存されている点。
- **リクエスト制御**: timeout、`AbortController`、多重送信対策がない点。

### 5. Codexの変更ルール
- 変更前に計画を提示し、ユーザーの合意後に実装する。
- 依頼外の変更はしない。
- エラーを発見しても、勝手に修正せず報告する。ただしユーザーが明示的に「自律的に修正してよい」と指示した作業範囲内では、自律修正してよい。
